## 1. 目标与完成标准

### 1.1 产品目标

将当前相对独立的 Jira、代码仓库、OpenAPI、Figma 和报告功能整合为统一流程：

```text
Jira Ticket
  → 需求分析
  → 代码/API/Figma 影响分析
  → 人工审核
  → Ticket 报告
  → Sprint 报告
  → 分享、导出和交付跟踪
```

### 1.2 总体验收标准

- [ ] 用户可以在 Sprint 中搜索、筛选、排序和选择 Ticket。
- [ ] 每个 Ticket 都有独立、可访问的详细报告。
- [ ] Ticket 报告同时覆盖需求、代码、API、数据库、Figma、测试、风险和待确认事项。
- [ ] 所有分析结论可以追溯到 Jira、代码仓库、OpenAPI 或 Figma 来源。
- [ ] 分析结果支持审核、驳回、重新分析和版本对比。
- [ ] Jira 或关联资产变化后，系统能够识别报告已过期。
- [ ] Sprint 报告可以预览、选择 Ticket、导出和分享。
- [ ] Viewer、Member、Admin 权限与写操作限制一致。

## 2. 实施前准备

### 2.1 数据模型设计

- [ ] 新增 `analysis_runs`，保存每次分析运行，而不是覆盖旧结果。
- [ ] 新增 `ticket_reviews`，保存审核状态、审核人、审核时间和审核意见。
- [ ] 新增 `ticket_artifact_links`，统一关联 Ticket 与代码源、API Spec、Figma 分析、测试计划。
- [ ] 新增 `report_snapshots`，保存已发布报告的固定版本。
- [ ] 新增 `sync_runs`，记录 Jira 同步状态和变更摘要。
- [ ] 新增 `audit_logs`，记录分析、审核、导出、分享和权限变更。
- [ ] 为现有 Ticket 数据补充 `updated_at`、`source_updated_at`、`analysis_stale_at`。
- [ ] 明确历史数据迁移和向后兼容策略。

建议核心关系：

```text
Project
  ├─ Sprint
  │   └─ Ticket
  │       ├─ AnalysisRun
  │       ├─ TicketReview
  │       ├─ CodeImpact
  │       ├─ ApiImpact
  │       ├─ FigmaImpact
  │       └─ ReportSnapshot
  ├─ CodeSource
  ├─ ApiSpec
  └─ FigmaSource
```

### 2.2 公共状态定义

- [ ] 分析状态统一为：`pending / queued / running / completed / failed / stale`。
- [ ] 审核状态统一为：`unreviewed / in_review / approved / rejected`。
- [ ] 报告状态统一为：`draft / published / archived`。
- [ ] 所有状态在后端枚举、前端类型、界面文案中保持一致。

### P0-06 分析时效与依赖失效

**目标**：任何输入资产变化后，都能判断分析结果是否仍然有效。

#### 实施项

- [ ] AnalysisRun 保存 Jira 更新时间、代码 Commit SHA、OpenAPI 版本和 Figma 版本。

- [ ] 任一来源变化时标记受影响分析为 `stale`。
- [ ] Ticket 列表和报告页显示过期原因。
- [ ] 支持按模块重新分析，而不是强制重跑全部模块。

#### 验收标准

- [ ] 用户能明确知道报告基于哪个版本的输入生成。
- [ ] 过期报告不能无提示地发布。

## 4. P1：分析质量与工程化

### P1-01 深度代码影响分析

- [ ] 扫描代码内容，而不只是文件路径。
- [ ] 提取类、函数、路由、数据库模型、迁移和测试文件。
- [ ] 建立符号引用和模块依赖索引。
- [ ] 支持多仓库和多服务聚合分析。
- [ ] 为每个受影响文件提供影响原因和证据。
- [ ] 区分新增、修改、删除、配置和测试变更。
- [ ] 显示代码源、分支、Commit SHA 和扫描时间。
- [ ] 返回可能遗漏区域和总体可信度。
- [ ] 获取 Ticket 影响时返回最新版本，而不是任意历史记录。

#### 验收标准

- [ ] 用户可以从报告中的文件直接跳转到仓库对应位置。
- [ ] 影响结果至少包含文件、符号、原因、变更类型和可信度。

---

### P1-02 API 真实影响分析

- [ ] 将 AI 候选接口与项目 OpenAPI Spec 对照。

## 8. 验证清单

> 根据项目约束，实施过程中不自动生成测试文件，也不自动运行测试；需要执行测试时应单独确认。

### 功能验证

- [ ] 新建项目并导入 Sprint。
- [ ] 对单个 Ticket 执行分析。
- [ ] 关联代码源、OpenAPI 和 Figma。
- [ ] 查看 Ticket 独立报告。
- [ ] 驳回分析并填写意见。
- [ ] 重新分析后验证审核状态失效。
- [ ] 批准分析并加入 Sprint 报告。
- [ ] 发布、导出和分享 Sprint 报告。
- [ ] 修改 Jira Ticket 后重新同步。
- [ ] 验证旧分析被标记为过期。

### 权限验证

- [ ] Viewer 无法执行写操作。
- [ ] Member 无法管理计费和成员。
- [ ] Admin 可以批准和发布报告。
- [ ] 跨 Workspace 访问返回拒绝或不存在。

### 数据一致性验证

- [ ] 重复同步不会创建重复 Sprint 或 Ticket。
- [ ] 删除项目会正确处理关联资产。
- [ ] 历史 AnalysisRun 不会被重新分析覆盖。
- [ ] 已发布报告快照不会随最新分析变化。
- [ ] 报告引用的代码 Commit、OpenAPI 和 Figma 版本可追溯。
